# Assisted native bootstrap on iOS 27.2.1

Status: prepared for physical validation. The current experiment allows App Store utilities and a user-authorized native pairing. It does not use Safari OTA, an existing pairing, a desktop, enterprise signing or a purchased certificate. Keep all existing installations intact.

## Components and reuse

| Component | Role and reuse boundary |
| --- | --- |
| Open Minis 1.16+ | Official App Store utility running the sandboxed terminal used by the upstream bootstrap. Use the App Store build. Its published source is GPL-3.0 and is not incorporated into Zag Store. [Source and license](https://github.com/OpenMinis/OpenMinis) |
| LocalDevVPN | App Store utility for a local developer tunnel. Use the official app. No source or redistribution permission is assumed from the listing. The VPN provides transport, while iOS pairing and installation authorization remain separate. [App Store listing](https://apps.apple.com/us/app/localdevvpn/id6755608044) |
| siboot | Runs in the Open Minis native environment and requests a fresh iOS 27 pairing through the Settings passcode/code flow. The documented route signs and installs SideInstaller using the user's Personal Team. Its current Rust crate declares MIT. Check notices and dependency terms before copying or distributing any part. Use the upstream release flow for this test. [Bootstrap source and prerequisites](https://github.com/FrizzleM/siboot/blob/main/minis/README.md) · [Crate metadata](https://github.com/FrizzleM/siboot/blob/main/minis/Cargo.toml) |
| SideInstaller | The upstream native client can sign and install a custom IPA via the paired device installation service. The published license restricts commercial use and redistribution of official binaries without written authorization. Use upstream distribution for personal testing. Do not embed, mirror or repackage it for Zag Store. [Implementation notes](https://github.com/FrizzleM/SideInstaller/blob/main/NOTES.md) · [License](https://github.com/FrizzleM/SideInstaller/blob/main/LICENSE.md) |
| Zag Store | Already provides explicit **Pair This iPhone**, native anisette and Apple ID sign-in, scoped certificate/key storage, compatible-profile readback and renewal. It is the target app in this test. It creates its own pairing locally after launch, through the normal Settings prompt. |

The bootstrap and signer are third-party code. Review the upstream source and release before using them with a test Apple ID. The upstream terminal flow uses its own authentication implementation. This does not establish that it shares Zag Store's native anisette or signing Keychain. Enter credentials only in the reviewed local workflow. Zag Store's website receives no credentials, verification codes, pairing records or private keys. Use the current Open Minis route only. The legacy enterprise section is outside this test. Stop if the route proposes any policy bypass, certificate revocation, app removal, existing trust reuse in place of the first pairing, or an overwrite.

## Physical procedure

1. **Prepare capacity.** Use stock iOS 27.2.1, Wi‑Fi and Developer Mode. Prefer a consented clean test phone. Establish room for SideInstaller and the separate Zag Store install if both are to remain installed. Do not infer free slots from bundle IDs, remove apps, or proceed past a capacity error. Record the starting Zag Store bundle ID privately or use the already verified AppTesters ID `com.cwd43.gu29` for that installation.
2. **Prove the upstream bootstrap first.** Open the [official SideInstaller install page](https://sideinstaller.net/install.html) on the phone. Follow its Open Minis and LocalDevVPN section, approve the new pairing in iOS Settings, and authorize the Personal Team install. Launch SideInstaller before proceeding. A successful install with a reused pairing does not satisfy the first-pairing test. Stop at the first failure and record the sanitized stage.
3. **Use the official unsigned target.** Download [Zag Store Beta 3](https://github.com/zagstore/zag-store-releases/releases/download/v1.0.0-beta.3/ZagStore-1.0.0-beta.3.ipa) to Files on the phone. The official asset metadata and local copy match SHA-256 `da743f30f32723ab2bb16051734caa109fd75d1fdaa292cdcb70c968d582f741`. Its bundle ID is `app.zagstore.ios`, version `1.0.0`, build `3`. [Release metadata](https://github.com/zagstore/zag-store-releases/releases/tag/v1.0.0-beta.3)
4. **Install as a separate app.** In SideInstaller choose **Custom .ipa** and select that download. Use the same free Apple ID and Personal Team used for the bootstrap. Confirm the team-scoped destination is distinct from all existing Zag Store installations, particularly `com.cwd43.gu29`. The expected native-style mapping is `app.zagstore.ios.<TEAM>`. Stop if the destination cannot be confirmed before authorizing installation, or if iOS offers to replace an installed copy. Decline revocation or certificate replacement. Record successful installation and successful launch separately. Verify the existing Zag Store still opens.
5. **Check identity and renewal separately.** In the new copy, connect LocalDevVPN, pair through **Settings → Installation → Pair This iPhone**, and authenticate the same Apple ID. Inspect the installation details for the actual team, signer, mapped identity and effective expiration. Attempt profile-only self-renewal only if the app reports eligibility and the resulting profile can extend validity. A new install may have no meaningful expiry extension yet. A refresh pass requires compatible-profile device readback and durable verified expiry. Never use a full reinstall to obtain a pass.

## Known continuity blocker

The current running-installation enrollment checks the exact executable signer against account- and team-scoped Keychain signing material. Signing with SideInstaller may produce a certificate whose private key exists only in the third-party signer. Signing in again with the same Apple ID and team does not move that key across app sandboxes. The current code therefore cannot be assumed to adopt or renew a SideInstaller-signed Zag Store installation. This does not prevent testing first pairing, installation and launch. A successful physical install should precede any design change for renewal. Evaluate a profile-only adoption design using the running code, authenticated account ownership, exact certificate evidence and device profile readback before considering any credential handoff. Do not export passwords, private keys, session tokens or pairing records for this experiment. [Production ownership check](../../Feather/Utilities/ZagNativeAccountInstall.swift#L731)

Report only the iOS version, whether fresh pairing appeared, bootstrap launch, target install and launch, preservation of the original installation, and the sanitized ownership/renewal result. No screenshots containing codes or account information are needed.
