# Apple ID maintenance acceptance

## Physical iPhone checks

1. Install the development build on a clean stock iPhone. Start LocalDevVPN and complete installation pairing. Authenticate a newly created Apple ID with two-factor authentication, then add a second account. Activate each account in turn and confirm that the other account stays signed in.
2. Sign and install an app with extensions using each account. Launch both apps. Check that the Apps page records the earliest verified component or certificate expiration. Confirm that ordinary certificate signing and signed-only installation still work.
3. On Apple IDs, open each account and refresh its capacity. Compare the account's App IDs and certificates with the portal and confirm that extension App IDs count separately. Check Device Capacity and confirm the count is labelled as verified coverage. Unknown slots should leave the iOS installer available.
4. Enable Automatic Refresh and Expiration Notifications in Signing Options. Test granting and denying notifications. Use a naturally approaching expiry or a device test fixture. Confirm that renewals are eligible at 48 hours, compatible work uses profile-only readback, and the last-success time advances only on verified renewal. Run a manual batch around the same time and confirm it cannot overlap.
5. Allow the device to deliver the 48-, 24- and 6-hour reminders and the expiration reminder. Confirm the contents omit account details. Renew one app in a group and confirm the reminders still reflect the other app. Test Refresh All on the notification from a cold launch, including after device unlock.
6. Test a batch with one signed-out account and one working account. Reauthenticate only the original account and retry. Repeat with network loss, pairing unavailable, and a certificate that needs repair. Confirm that only recoverable errors retry and that no certificate is revoked.
7. On a Personal Team Zag Store installation with locally attributable signing credentials, tap Verify This Installation. Confirm that Refresh All changes the effective expiration through profile readback and keeps the running process alive. Restart and confirm the date persists. Repeat with Home Screen Quick Actions and Shortcuts. Test an unrelated signer and confirm verification fails closed.
8. Use Sign Separate Copy to select the second authenticated account. Test a successful install and launch, a target already installed, and a device installation refusal. Confirm that the original app and its receipt remain intact in all three cases.
9. Time three compatible apps on a healthy connection and compare with the physical sub-five-second baseline at `ee6b835c`. Inspect Copy Diagnostics to confirm the coalesced handoff is used. Repeat with the app unlocked, suspended and through a Shortcut. Confirm Settings and account screens in light and dark appearance.
10. Check an existing signed Zag Store update through its manifest and installation verification path. Self-renewal should leave the version and build unchanged.

iOS chooses when to launch a background task. LocalDevVPN and paired transport must be available at execution time. An expired Zag Store installation cannot schedule its own repair if iOS prevents it from launching. Recover using a trusted signing tool and the original account, team, mapped bundle ID and compatible entitlements. Preserve the existing installation where possible and review data and Keychain access before any reinstall. A different signing identity may require a separate install and may lose access to existing data.

## Source audit

- Native sessions and keys are stored in account- or team-scoped Keychain records. The inspected secrets and keys use this-device-only protection after first unlock with synchronization disabled. Explicit sign-out journals local credential removal, while installed ownership receipts remain independent. The device-level ADI identity is shared and isolated from account session storage. Local signing-header failures now preserve the available session for recovery.
- Developer services use the existing HTTPS host allowlist, system TLS validation, ephemeral network sessions and request bounds. Profile-only renewal continues to use account-scoped discovery, cancellation checkpoints, serialized device mutations and profile readback. Key matching and certificate replacement still use explicit consent where required.
- Native signing diagnostics redact labelled credential and anisette fields. Credential material does not belong in the account-capacity UI, notification payloads or automatic-refresh state. Production telemetry retention and reverse-proxy logs require separate verification against deployed configuration.
- Imported signing archives and retained native archives are inspected before extraction using the ZIP directory read by the extractor. Paths are checked for confinement and the declared entry count and aggregate size are bounded. Retained archives and signing receipts use private app storage and protected files. A complete review of extractor resource behavior and interrupted full-signing transactions still requires dedicated coverage.
- The repository's anisette service runs loopback-only behind HTTPS with bounded headers, bodies, connections, worker lifetimes and service resources. The checked-in unit uses a dedicated account, private temporary directories, filesystem and syscall restrictions, and localhost-only networking. The deployed reverse proxy still needs independent verification for request-rate limits, upstream timeouts and log redaction. This change requires no server deployment and makes no changes to live infrastructure.
